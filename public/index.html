4 STARTER RECIPES

Templates are illustrative starting points, not hardened or production-validated appliances. Your selected RHEL version is retained. Loading a template replaces the current rows after confirmation.

Container tooling. A whole operating system.

RHEL image mode uses a bootc base image that contains the kernel and userspace. You define the OS with a Containerfile, publish it to an OCI registry, and install it on a VM or physical host.

Compose→Build→Publish→Boot→Update

What belongs in a recipe?

Packages: OS software installed at build time.
Commands: build-time customization, such as creating files and setting permissions.
Services: enable units to start when the installed system boots—not during the build.

Beyond RUN: files and settings

The editor currently turns packages, commands, and services into RUN instructions, with a fixed FROM base. Containerfiles can also use COPY to include local files, such as a service unit or application configuration. Those files must be included in the build folder and committed alongside the Containerfile for a workflow to find them. File steps are not available in this editor yet.

LABEL adds image metadata; ARG provides build-time options; ENV sets environment variables; and WORKDIR changes where later commands run. None of these is a safe place for secrets. An operating-system image is not an ordinary application container: preserve the bootc base image's startup and user defaults unless its documentation calls for a change.

What does not belong in it?

Secrets, machine-specific credentials, and persistent application data. Plan separately for configuration under /etc and state under /var. An OS rollback is not a database rollback.

About this prototype

These are illustrative templates. The UI checks input shape, not whether packages exist, shell commands are valid, or the resulting OS boots. Verify against your selected RHEL release and official documentation.

Start with a disposable Linux build host.

You need Podman, Red Hat registry access, package repository entitlement, and write access to your destination registry. Registry authentication and package entitlement are separate prerequisites.

For the first installation
Use bootc-image-builder to derive a disk or installer artifact from the OCI image. Provide users, disk layout, and target-specific configuration. Provision the VM or hardware from that artifact; later OS updates come from the registry.
After installation
sudo bootc status
sudo bootc upgrade
# Activate in a maintenance window:
sudo systemctl reboot

# Prepare a previous-deployment rollback:
sudo bootc rollback
sudo systemctl reboot
Execution is deliberately out of scope here. Export and review the recipe. Test first boot, service behavior, upgrades, and rollback before rollout.


Your recipe, on repeat.
Generate a build-and-publish pipeline for a preconfigured self-hosted Linux runner. Commit your exported Containerfile at the repository root; the pipeline builds that committed file, not the browser's unsaved state.
Before your first run
    Use a disposable or dedicated runner with Bash, Podman, and RHEL package entitlement configured for container builds. Restrict runner access and credentials to trusted, protected branches. The pipeline uses a private temporary registry-auth file and cleans it up on exit.
    Review→Build→Boot-test→Sign→Publish
    Practical delivery gates
    1. Build from reviewed source and pin production dependencies.
    2. Scan the image and retain its SBOM.
    3. Boot a disposable VM and verify your enabled services.
    4. Test upgrade and rollback, including application compatibility.
    5. Sign and publish an immutable image version.
    6. Promote to staging, then roll out through controlled production rings.
    These generated starters build and publish only. They have not been executed against your CI environment. Add boot tests, scanning/SBOM, signing, and protected promotion before production. Versioned commit-and-run tags avoid overwriting latest; enable registry immutability if you need enforced immutable releases.
